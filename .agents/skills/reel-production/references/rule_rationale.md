# Why each rule and default exists — measurements and examples

The reel-production rules before the 2026-10-06 consolidation, kept verbatim: the measurements, Bad/Good pairs and
incidents behind each rule. SKILL.md now states the rules briefly; read the matching entry here when a rule is unclear,
or before overriding a craft default.

## The thirteen rules (2026-10-05 wording)

**#1 — Route before authoring**: run `route plan` and decide each shot's route (blender | generative | hybrid) from declared features, never from how the goal text sounds. Exact geometry/motion/identity/anchored labels stay in Blender; generation only owns phenomena, real-place atmosphere or beyond-asset realism. Instead of guessing, declare `route_features` and let the rules decide; ask the user when the rule is R0 (low confidence).
**#2 — No text in generated frames**: generated video garbles letters. Every generation prompt says "no text, no letters, no captions" and contains no quoted strings; titles, numbers and labels are added in edit from 3D anchors or measured 2D anchors. Structure comes from the input video; the words own the look and what is added (`route.generative.prompt_spec`: look / keep / add / forbid). Never ask the prompt to enforce counts or positions — the A/B ignored "nothing is added" and invented ceiling louvres; the gate and the person picking the take catch it.
**#3 — GPU by default**: render with `STUDIO_RENDER_DEVICE=GPU` (Metal, ~11× faster outside the Codex sandbox). Only when the user limits computer load use CPU, one worker, one small frame first — and disclose it.
**#4 — Real scale before look**: run the scale audit (look_report.json `passes.scale`) and fix scale before judging lighting, DOF or materials; a 8.6× oversized scene makes every physical look setting wrong. Author-called `rescale_scene` refuses scenes with baked camera keys — rescale first, then bake the camera. Tag what is not the subject before any look or control pass — earth/sky shells `studio_scene_role: environment_shell`, fog `atmosphere`, markings and window bands `clutter`, emissive panels `light_fixture` — because every mesh-sweeping pass (lighting bounds, clay, perfection, control depth range, ray-cast guards, reveal cuts) reads that one table; in photoreal s02 the 400 m earth box sized the lit bounds (practical lamps hung at z +64 m, above the station), and untagged it would also set a control's far plane and be bevelled and cut like a part. Bad: hiding the shell in the author script. Good: one tag, every pass consistent. → `references/scene_roles.md`
**#5 — Never manufacture approval**: approvals, budgets and human verdicts come only from the user's own words. Candidate ≠ approved master.
**#6 — Camera energy, explored not guessed**: decide `camera.energy` per shot; make high-energy cameras with `camera.rig`, never with a camera loop in the author script. For high-energy or hero-motion shots explore 2–3 alternatives in the workbench (`set_camera_rig` → `variant_save` each) and pick one from `workbench compare` at the same frames, then `workbench commit --chosen-variant X --why "..."` — the first idea is usually safe and flat (the stiff jet chase). Exploration costs no version and no repair budget. Bad: render the first orbit you typed. Good: low chase / side sweep / close pass compared at frames 1, 45, 90; side sweep chosen because its guards pass and near_field_ratio is highest. A camera that travels is a `camera.move`, not hand keys or a hand-timed speed: choose the move from what the narration shows (enter an opening → `dive_through`, between members → `pass_between`, down a section → `descend_levels`, come down in front of a ground cut and push into the structure → `section_push`, any other route → `waypoints`) and leave its timing to a motion style (`motion style learn` from the references, else an existing style) and `camera fit --apply`. Hand keys run at constant speed — the Samsung blockout reached 40 % of the reference's motion with no head rush and no settle. Bad: three keys 6 m apart, constant speed. Good: `dive_through(opening=road.opening, below=concourse)` + `style: archcutaway`, then `camera fit --apply` moves predicted burst_share 0.88→0.51 and hold_frac 0.83→0.42 into the style quartiles. → `references/camera_rig.md`, `references/workbench.md`
**#7 — Spec before shape**: decompose every subject the request names into a subject spec (`subject init/lint`): trace every request phrase to a requirement, source real dimensions (≥ 2 sources for a real subject), list identity features with a verify method, and build geometry that makes a claim from spec builders (loft/wing/revolve/sweep/profile/wall/array, with ops), never from numbers typed into the author script; appearance shape is free (spec ops or any bpy) and illustrative. The shape decides everything downstream: a hybrid restyle copies the blockout silhouette, so a toy-proportioned model stays a toy. Polish camera and look only after `fidelity_report.json` passes. Building elements (stairs, escalators, railings, girders, light rows, track, slabs, ducts) come from the verified exemplars placed with data edits, never from boxes standing in for them: the model can only keep structure the control pass shows (a box station hall's control clay measured 13.5 trackable tiles against the reference's 32–44). Bad: a 14 m tilted box as an escalator. Good: `escalator` exemplar (31 tread+riser groups, balustrades, handrails) at one storey's rise. Repeated background that no label, reveal or check names (trees, crowds, rubble, tunnel rings) is `scatter` (Geometry Nodes instances, one host), not copied objects; subjects and anything anchored stay spec geometry — an instance has no name to anchor, measure or cut. Context around the subject — streets, facades, traffic, roofs, signs — comes from the environment kits (`env_kits.street`, fill functions `along / blocks / on_top / on_front / traffic`, verified kit exemplars), never bare boxes: the box city measured 0.10 saturation and 0.016 shadow detail against the reference's 0.19–0.25 and 0.023–0.13 (look style `archcutaway_night`), and lit windows exist only as a shader (`window_grid`), never thousands of window objects. Bad: random boxes with one lit band per floor. Good: `street(path, density='urban_dense', night=True)` — per-window lit ratio and colour temperature, head/tail-lit traffic that never crosses the opening. → `references/subject_fidelity.md`, `references/building_elements.md`, `references/scatter_simulation.md`, `references/environment_kits.md`
**#8 — You decide structure, code decides numbers**: you choose parts, builders, relations, claims and `free` bounds; numbers come from sources, `subject trace` (drawing pixels at `px_per_m` through a datum), `subject fit` (Nelder-Mead on silhouette IoU with sourced dimensions held) or `subject from-dxf`. LLM-picked numbers are where the toy jet and the 0.62 m drawing offset came from. Place parts with `relations` (attach/align/through/on_surface/symmetric) and state connections as `assembly_claims` (contact/no_interference/through/cover/clearance/no_floating), not typed coordinates — a typed coordinate has no meaning to check. Bad: wing `"location": [0, -0.48, -0.48]` guessed from the picture. Good: `subject trace --register --part wing` → candidate with pixel evidence → `subject fit` → `relations: attach fin/-z → fuselage/+z`. → `references/subject_fidelity.md`
**#9 — One diagnosis per build, best version kept, 3 rounds**: every subject-shot rebuild names the single failure it addresses (`shot build --diagnosis`, `workbench commit --diagnosis`). A build that scores below the best version is reverted automatically; after `limits.look_iterations_per_shot` (3) non-improving builds the next one is refused (`REPAIR_BUDGET_EXHAUSTED`). This budget counts only while fidelity fails; look and appearance iterations on a passing shot are free. When stuck — in order: 1) re-trace or add stations where `silhouette_*.png` diverges; 2) widen `free` bounds or add free parameters; 3) split the part; 4) new or better reference (CAD, second view); 5) ask the user (they reset the budget with `repair reset --reason`). Forbidden: lowering `min_iou`/tolerances, deleting a claim, or editing a spec number by hand to pass. → `references/workbench.md`
**#10 — Freedom by declaration**: when the shot needs a subject to differ from its sources on purpose (a bolt enlarged to be legible, an exploded view where parts float, a stylised silhouette), declare it in the spec's `deviations` (`check`, `factor` / `min_iou` / `waive`, `reason`; real subjects with a large change also `user_evidence` in the user's words). The check then judges the declared target and the report keeps the original expectation, so a deliberate change is visible and a mistake is still caught. Instead of loosening tolerances or deleting checks (still forbidden), declare. Unused deviations are reported; remove them.
**#11 — Shot role decides what generation owns**: set `route.role` on every generative/hybrid shot. `explain` (parts, positions, labels, dimensions) is Blender, or a hybrid restyle that passed the structure gate; labels and graphics ride only on that. `mood` (establishing aerials, interiors at large, transitions) may be generated and carries captions only. Measured 2026-10-05: all six A/B restyles failed the structure gate (IoU 0.07–0.23) while looking photoreal, and edge preservation could not tell a re-surfaced layout from a moved one — so a generated take is never an explain shot by looks alone. Bad: a hybrid column shot that failed structure, used anyway because it looks real. Good: the same take as a `mood` interior with a caption, chosen by the user in their words; the column explanation stays Blender with labels. What the model is shown follows the role too (`generate inputs`): explain gets the control clay + depth it is judged against, mood gets the look render — clay carries no lit window or lamp (control passes override every material, emission 0), so a mood shot fed clay invents its own lights (W9). → `references/routing.md`, `references/generative_safety.md`
**#12 — Readable frame before rich frame**: every shot is judged in the frame, not in the world. Hold the horizon where the reference keeps it (`move.framing.horizon_v`, learned with `composition style learn`; ~0.40 for the cutaway aerials) and keep sky by rule (`street(..., sightline=...)`), because aiming at the target the whole way put s01's horizon at v 0.19 and its sky at 0.04 against the reference's 0.41 / 0.21 — the head read as "looking down". Words are 2D `shot.titles` checked inside the title safe rect every frame (x .11–.89, y .14–.65), never 3D text (`graphic_in_frame` fails it: s01's title was 78 % above the frame for 30 frames). Arrows that ride a moving camera are `space: "screen"` and must pass legibility (≥ 0.08 H long, head/shaft 3–4.5, ≥ 100 px of 1080 off the flight line) — on the flight line an arrow reads as a crack. A structure is shown as a section (`section_push` + `section.stage`: soil, poché, interior light), never by flying down its corridor. Bad: dive through a hole and look down the station's length with a 3D title placed for an older camera. Good: level aerial with sky (horizon 0.40), 2D receding title, the ground cut in front of the station showing five lit levels, then the push in (s01 v0023). → `references/camera_rig.md`, `references/titles.md`, `references/explainer_graphics.md`, `references/section_staging.md`
**#13 — The topic decides what fills a shot, and the user signs it off**: before any level, floor or interior is filled, draft a `fill_brief` (topic, then per level `subject` = what the shot explains, `identity` = the fewest cues of where we are, ≤ 2 kinds, `ambient` = life ≤ 4/100 m²; every item with a traced `why`), `fill propose`, show the sheet, ask what to add or remove, record the user's words verbatim with `fill revise`, and `fill approve` in their words. A place's usual furniture is not a reason: measured on s01, the empty station read as a corridor and a station catalogue would have hidden the columns the story is about. Renders and paid generation refuse an unapproved or changed brief; the build gates refuse a seen level with nothing from the brief (`FILL_LEVEL_EMPTY`, or declare it `void` with a note), a buried subject (`FILL_SUBJECT_HIDDEN`) and fill no item explains (`FILL_OFF_BRIEF`). Missing elements are modelled as exemplars, never boxes. Bad: fare gates, kiosks and benches because it is a station. Good: rebar columns as subject, screen doors and one train as identity, light people; fare gates excluded because they hide the columns; the user then adds or removes in their words. → `references/fill_brief.md`

## After the consolidation (2026-10-06): every value reachable, nothing written that nothing reads
- **Rule #3, second half** (the user's words reach every value). Incident: the storyboard word-ops reached only a move's
  distance / height / angle knob, so "pass by longer" (slide `span`) and "less cropped at the end" (macro_push
  `detail_fill`) could not be said; earlier the crane and dive_through "higher" knobs named `to_height_m` /
  `start_height_m`, which the moves never read - the build passed and the frame did not change. Fix measured: one edit
  grammar (`studio/shot_edit.py`: set / add / remove by path) for storyboard, fill brief and workbench; declared-reads
  tables checked against the code by running it on recording dicts (move params `camera_moves_core.PARAMS`, action params
  `action_params.py`, rig/timing/move keys by context `camera_keys.py`, graphics/titles/fill items by kind
  `content_keys.py`, scene kits/section/materials `layout.scene_unread`); `validate_shot` refuses what nothing reads.
  robot_joint takes were then edited by words only: A 0.75× closer, B `detail_fill` 0.6→0.4, C `span` 0.8→2.0. The
  checks found two more silent no-ops (a user `timing.distance_m` overwritten by compile_move; `camera.target_anchor`
  read by nothing - now the keyed camera's subject, CAMERA_ANCHOR_OUT_OF_VIEW) and one crash (a screen arrow starting at
  frame 0). Bad: "the move has no knob for that". Good: `set /camera/move/params/detail_fill 0.4` → sheet line
  `/camera/move/params/detail_fill: 0.6 → 0.4`.

## Gate kinds (2026-10-07): taste warns, broken output blocks
- **Craft defaults, taste gates.** Incident: engine_cutaway2 ran under the old default (every softenable gate an error).
  All three discarded builds were taste gates - `KEY_PART_SMALL` on valves plainly visible at 0.17 % of the frame and
  `FRAME_EDGE_CUT` - each after the build had passed every mechanism check; s02 and s03 ended with no version and about
  20 minutes went into restaging. The two real defects of the run (a cover gap, a timing slit) were seen by eye. Fix:
  every softenable gate declares a kind in `studio/gates.py` (`broken`, `budget`, `taste`); the default
  (`explain-strict`) blocks broken and budget gates and reports taste gates as warnings; `all-strict` restores the old
  behaviour, `policy.gates` tightens or loosens one code. A unit test fails until a new softenable gate has a kind.
