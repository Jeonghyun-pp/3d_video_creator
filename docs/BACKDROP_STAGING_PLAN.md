# 배경 먼저, 관계를 지정해서 (2026-10-06)

사용자 판단: 생성 배경을 나중에 붙이면 피사체가 떠 보인다 - 배경을 먼저 정하고, 배경과 객체의 관계(받침·시점·조명)를
지정해서 Blender 장면을 그에 맞게 만든다. 측정 근거: robot_joint 방법 2(배경 3장 합성)는 기어는 정확했지만 세 장 모두
(1) 받침·접지 그림자 없음 (2) 조명 불일치(배경 밝고 차가운 낮빛 / 기어 어두운 스튜디오)로 떠 보였다.

## 원칙
- 관계는 데이터 하나(`shot.scene.backdrop.relation`)이고, 배경 프롬프트와 Blender 장면이 **둘 다 그것에서** 나온다(어긋날 수 없게).
- 특정 장면이 아니라 어떤 주제든: 받침(작업대·바닥·없음), 시점(내려다보는 각도), 조명(키 방향·색온도, 배경 반사).
- 룩 코드(수정 금지 묶음)는 건드리지 않는다: 룩은 `studio_keep_light` 조명을 유지하므로 관계 조명은 실용 조명으로 넣는다.

## 단계
| # | 내용 | 파일 | 검증 |
|---|---|---|---|
| B1 | 스키마: `backdrop.relation {support {kind: bench/floor/none, material, margin}, view {elevation_deg}, light {key_side, key_kelvin, fill_kelvin, reflections}}`; `image`는 선택(관계를 먼저 정하고 배경은 나중에 생성) | shot.schema | 스키마 테스트 |
| B2 | 받침면: 레이아웃이 인스턴스를 지은 뒤 피사체 아래(최저점)에 작업대/바닥을 둔다 - 카메라 무브·리그 가드가 보는 장면 형상(카메라가 받침을 뚫지 않음) | layout(Blender) | 스모크: 접촉(간격 0), 크기 |
| B3 | 조명·반사: 관계의 키/필 방향·색온도로 실용 조명(카메라 기준 방향, 피사체 크기로 거리), 배경 이미지로 반사 돔(카메라에 안 보이고 금속에 비침) | backdrop.py | 스모크: 조명 유지됨, 돔 카메라 비가시 |
| B4 | 시점 일치: 카메라 무브의 elevation과 관계의 view가 10° 넘게 다르면 lint 경고 | layout.lint | 단위 |
| B5 | 배경 프롬프트 합성: `backdrop-review --shot S --place "…"` → 관계(시점·받침·조명 방향·색온도·가운데 비우기)에서 문장을 만들어 장소 설명 앞에 붙임 | generative/backdrop.py | 단위: 관계 바꾸면 프롬프트 바뀜 |
| B6 | robot_joint 실측: 관계 지정 + 배경 3 → 렌더 → 기존 방법 2·Seedance와 비교 영상 | - | 눈으로, 사용자 판단 |

범위 밖: 배경 이미지 분석으로 조명 방향 자동 추정(지금은 관계가 프롬프트를 정하므로 불필요), 배경 영상(움직이는 배경).
